# ADR 0002：自建先行，保留扩展接缝

- 状态：已接受（D1，2026-11-17 修订）
- 日期：2026-11-16
- 决策者：项目负责人

## 背景

Meatus 的 V1 定位是**完全开源、个人 / 小团队自托管**：一台公网 server + 若干内网 client，单二进制、TOML 配置、零数据库、零 Redis。

早期设计曾评估过“托管控制面 + 多租户 + 计费”的形态。该形态会显著增加账号、计费、运维和多租户隔离的工作量，而核心隧道的数据面与自托管场景并不需要这些能力，因此 V1 明确不做独立控制面产品，也不将其纳入排期。

## 决策

- V1（M0–M6）只交付自托管形态：单二进制 `meatus`，TOML 配置，本地文件即配置源。
- 不建 `meatus-ctrl`，不接 PostgreSQL / Redis，不做 token 签发服务、计费或多租户 UI。
- 从 M0 起保留五个扩展接缝，relay 只依赖 trait，方便社区或第三方在 Apache-2.0 基础上扩展：
  1. `AuthProvider`：本地 token / 未来可接外部鉴权。
  2. `ConfigSource`：本地文件 / 未来可接外部配置快照。
  3. `UsageSink`：本地 trace / 未来可接用量上报。
  4. `NameAllocator`：本地端口池 / 未来可按租户分区。
  5. `QuotaPolicy`：本地放行 / 未来可按策略限额。
- 所有资源标识从第一天就是三级：`tenant_id / client_id / proxy_name`，V1 固定 `tenant_id = "default"`。
- relay 保持无状态、可多实例；任何外部控制面都不得进入数据面。

## 代价

- M0 多花约 2 人日写 trait 与空实现。
- 部分本地实现暂时“看起来多余”（例如单租户仍要带 tenant 参数），但换来后续扩展时数据面代码基本不动。

## 验证方式

- M0 的 `cargo test` 覆盖接缝的本地实现。
- 第三方扩展控制面时，只依赖 `core` / `proto`，不修改 relay 数据面。
