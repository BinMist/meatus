## 2. 目标与非目标

### 2.1 目标

保持旧客户端兼容，把传输层从「单 TCP + yamux」推进到：

- `MEATUS/2` 加法协商，旧 1.2 / 1.3 客户端继续接入；
- QUIC 可选传输，默认 TCP，`auto` 失败自动回落；
- 多入口与故障切换；
- IPv6 双栈；
- 连接池生产化（默认关闭）；
- `trace_id` / `connection_id` 贯穿；
- 优雅 drain；
- 可复现的 TCP / QUIC 性能基线；
- 脚本化兼容实验室。

### 2.2 非目标（本版不做）

- P2P、RTT 选路、流优先级、缓冲区调优；
- QUIC 会话迁移；只保证新连接恢复；
- 默认启用 QUIC；
- Windows 客户端、桌面 GUI；
- GHCR / GitHub Release；
- 引入数据库、Redis、外部控制面。

## 3. 兼容性契约

1. **默认行为不变**：未显式配置时，仍为 `TCP + TLS 1.3 + yamux`，`transport = "tcp"`。
2. **协议只做加法**：`MEATUS/2` 复用 `Hello.protocol_version` 与 `caps` 协商；未知字段忽略，不改变 `MEATUS/1` 消息语义。
3. **旧客户端优先**：1.2.1 / 1.3.0 客户端连接 1.4.0 服务端必须成功，不允许要求升级配置。
4. **新客户端可回退**：1.4.0 客户端连接 1.3.0 服务端时，自动回落 `MEATUS/1` + TCP。
5. **QUIC 永不为默认**：`transport = "quic"` 才强制 QUIC；`auto` 5 秒内失败回落 TCP；回落必须写日志与指标。
6. **配置向后兼容**：`server_addr` 继续有效；`server_addrs` 非空时才覆盖单地址；`[client.pool]` 缺省即关闭。
7. **可回滚**：任一新增能力都可用配置关闭；服务端回退 1.3.0 不需要数据迁移。

## 4. 拟定配置契约

> 下面是任务拆解用的草案，最终字段名由 `E1-01` / `D1-03` 定稿；定稿前不改生产配置。

服务端：

```toml
[server]
bind_addr = "0.0.0.0"
control_port = 7000

[server.quic]
enabled = false          # 默认关闭
bind_addr = "0.0.0.0"    # 支持 IPv6 字面量
port = 7443              # UDP
```

客户端：

```toml
[client]
server_addr = "tunnel.example.com:7000"
server_addrs = []        # 非空时优先，按顺序故障切换
transport = "tcp"        # tcp | quic | auto；默认 tcp

[client.pool]
enabled = false          # 默认关闭
size = 4
max_streams_per_conn = 64
idle_timeout_s = 300
```

## 8. 风险与应对

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 国内网络 UDP 被 QoS / 封禁 | 高 | QUIC 默认关闭；`auto` 5 秒回落；发布说明明确网络要求 |
| quinn / rustls 版本与现有 TLS 栈冲突 | 高 | D1-01 先做 spike；不通过则改用独立 TLS 配置，不阻塞 TCP |
| 连接池引入队头阻塞或泄漏 | 中 | 池键按 proxy/host；默认关闭；故障注入与任务泄漏测试 |
| 协议加法字段破坏旧客户端 | 高 | 兼容矩阵前置到 M1；未知字段忽略；旧客户端 fixture 来自正式 Release |
| IPv6 环境不足 | 中 | 用容器 / netns 构造 IPv6-only；文档给出回退 |
| 性能门禁不稳定 | 中 | 固定机器、固定参数、样本量；阈值留 20% 余量；报告入 CI |
| 范围蔓延到 P2P / RTT | 中 | 本版非目标写死；新增需求进 1.5 候选，不插入 1.4 |
