## 2. 目标与非目标

### 2.1 目标

保持旧客户端兼容，把传输层从「单 TCP + yamux」推进到：

- `MEATUS/2` 加法协商，旧 1.2 / 1.3 客户端继续接入；
- QUIC 可选传输，默认 TCP，`auto` 失败自动回落；
- 多入口与故障切换；
- IPv6 双栈；
- 连接池生产化（默认关闭）；
- `trace_id` / `connection_id` 贯穿；
- 优雅 drain；
- 可复现的 TCP / QUIC 性能基线；
- 脚本化兼容实验室。

### 2.2 非目标（本版不做）

- P2P、RTT 选路、流优先级、缓冲区调优；
- QUIC 会话迁移；只保证新连接恢复；
- 默认启用 QUIC；
- Windows 客户端、桌面 GUI；
- GHCR / GitHub Release；
- 引入数据库、Redis、外部控制面。

## 3. 兼容性契约

1. **默认行为不变**：未显式配置时，仍为 `TCP + TLS 1.3 + yamux`，`transport = "tcp"`。
2. **协议只做加法**：`MEATUS/2` 复用 `Hello.protocol_version` 与 `caps` 协商；未知字段忽略，不改变 `MEATUS/1` 消息语义。
3. **旧客户端优先**：1.2.1 / 1.3.0 客户端连接 1.4.0 服务端必须成功，不允许要求升级配置。
4. **新客户端可回退**：1.4.0 客户端连接 1.3.0 服务端时，自动回落 `MEATUS/1` + TCP。
5. **QUIC 永不为默认**：`transport = "quic"` 才强制 QUIC；`auto` 5 秒内失败回落 TCP；回落必须写日志与指标。
6. **配置向后兼容**：`server_addr` 继续有效；`server_addrs` 非空时才覆盖单地址；`[client.pool]` 缺省即关闭。
7. **可回滚**：任一新增能力都可用配置关闭；服务端回退 1.3.0 不需要数据迁移。

## 4. 拟定配置契约

> 下面是任务拆解用的草案，最终字段名由 `E1-01` / `D1-03` 定稿；定稿前不改生产配置。

服务端：

```toml
[server]
bind_addr = "0.0.0.0"
control_port = 7000

[server.quic]
enabled = false          # 默认关闭
bind_addr = "0.0.0.0"    # 支持 IPv6 字面量
port = 7443              # UDP
```

客户端：

```toml
[client]
server_addr = "tunnel.example.com:7000"
server_addrs = []        # 非空时优先，按顺序故障切换
transport = "tcp"        # tcp | quic | auto；默认 tcp

[client.pool]
enabled = false          # 默认关闭
size = 4
max_streams_per_conn = 64
idle_timeout_s = 300
```

## 8. 风险与应对

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 国内网络 UDP 被 QoS / 封禁 | 高 | QUIC 默认关闭；`auto` 5 秒回落；发布说明明确网络要求 |
| quinn / rustls 版本与现有 TLS 栈冲突 | 高 | D1-01 先做 spike；不通过则改用独立 TLS 配置，不阻塞 TCP |
| 连接池引入队头阻塞或泄漏 | 中 | 池键按 proxy/host；默认关闭；故障注入与任务泄漏测试 |
| 协议加法字段破坏旧客户端 | 高 | 兼容矩阵前置到 M1；未知字段忽略；旧客户端 fixture 来自正式 Release |
| IPv6 环境不足 | 中 | 用容器 / netns 构造 IPv6-only；文档给出回退 |
| 性能门禁不稳定 | 中 | 固定机器、固定参数、样本量；阈值留 20% 余量；报告入 CI |
| 范围蔓延到 P2P / RTT | 中 | 本版非目标写死；新增需求进 1.5 候选，不插入 1.4 |

### E1-04 协商失败与回退路径（done）

- 客户端：`establish_with_fallback` 先按 `PROTOCOL_VERSION=2` 握手；只有服务端返回 `1002 UnsupportedVersion` 才降到 v1 重连一次。认证失败、限流、TLS 错误等不触发回落。
- 日志：回落时记录 `attempted`、`fallback=1`、`code`、`reason`；会话建立后记录 `client_protocol=1`。
- 防循环：回落只允许一次；v1 仍失败按致命错误返回，交给外层退避重连。
- 兼容：未知 caps 仍只进 `ignored_caps`，不降版本、不失败。
- 验证：
  - `cargo test -p meatus-client --locked`：12 passed；新增 `1002`/非 `1002` 分类测试。

### D5-02 池配置与校验（done）

- 模型：`PoolSection` 挂在 `ClientSection`，对应 `[client.pool]`；字段 `enabled`、`size`、`max_streams_per_conn`、`idle_timeout_s`，默认 `false / 4 / 64 / 300`。
- 校验：`size` 1..=16、`max_streams_per_conn` 1..=1024、`idle_timeout_s` 1..=3600；即使关闭也校验，错误路径为 `client.pool.<field>`。
- 兼容：YAML 为 `client:` 下嵌套 `pool:`；管理面写回 proxy 时保留 `pool` 段。
- 示例：`config/client.example.toml`、`config/client.example.yaml` 已加入默认关闭的池段；`docs/USAGE.md` 增加字段说明。
- CLI：`meatus check` 客户端摘要新增 `pool     disabled` 或 `pool     enabled size=... max_streams_per_conn=... idle_timeout_s=...`。
- 验证：`config::tests::client_pool*` 5 passed；两份示例 `meatus check` 均 OK；config_edit YAML 用例确认池段保留。

### D5-03 池生命周期与上限（done）

- 协议：`Hello` 加法字段 7 `session_id`、8 `data_connection`、9 `pool_size`、10 `max_streams_per_conn`；旧客户端不填即普通控制连接。
- 服务端：主会话 Welcome 后按 `run_id` 建 `SessionPools`，主控制连接的 `OpenHandle` 入池；数据连接认证后按 `session_id` 加入同一池，租户 / client 不一致拒绝；主会话断开时统一取消。
- 选择与上限：`ConnectionPool::open` 选择在途流最少的连接，单连接达到 `max_streams_per_conn` 返回 `3002`；打开失败的坏连接自动移除后重试。
- 客户端：`size - 1` 条额外 TLS + yamux 数据连接，复用主会话 `run_id`；空闲超过 `idle_timeout_s` 关闭并按 1s 起指数退避重建；协议回落到 v1 时不建池。
- 兼容：所有 HTTP / HTTPS / SOCKS5 / TCP / UDP 服务端路由统一从 `Arc<ConnectionPool>` 取流；`enabled=false` 时池只有主连接，行为与 1.3 的单连接一致。
- 验证：core `pool::` 5 passed；server 49 passed；tunnel 11 passed / 1 ignored，其中 `pool_size_and_stream_limit_allow_two_simultaneous_tunnels` 用 `size=2`、`max_streams_per_conn=1` 验证两条并发隧道；全仓 190 passed / 1 ignored。

### D5-04 池指标与故障注入（done）

- 共享统计：`PoolStats`（`connections`、`opens`、`reuses`、`waits`、`timeouts`）由 `SessionPools` 与 `Metrics` 共享同一个 `Arc`，所有会话池聚合到全局口径。
- 指标：`/metrics` 新增 `meatus_pool_connections`（gauge）、`meatus_pool_opens_total`、`meatus_pool_reuses_total`、`meatus_pool_waits_total`、`meatus_pool_timeouts_total`（counter），均带 HELP/TYPE。
- 等待语义：池内无可用容量时 `waits + 1`，最多等待 5 秒；超时 `timeouts + 1` 并返回 `3002`，由 `PoolGuard` 归还容量并唤醒等待者。
- 故障注入：`broken_connection_is_removed_and_pool_recovers` 断开底层驱动后，`open` 返回 `Closed`，坏连接自动驱逐，补入新连接后恢复可用，`connections` 计数回到 1，无残留任务。
- 验证：core `pool::` 6 passed（含坏连接恢复）；server `metrics::` 2 passed（池 gauge / opens 计数）；全仓 193 passed / 1 ignored；clippy `-D warnings` 与 `cargo fmt --check` 全绿。
